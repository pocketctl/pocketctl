🎯 背景与运营模式

pocketctl 采用混合模式运营：

模式说明权益
SaaS 用户连接托管 Relay，由平台管理 按 users.plan 字段分层（free / pro）
Self-hosted 用户自己 docker compose up -d 搭建 始终享受 pro 权益，全部功能可用
参考 GitLab、Sentry 等开源项目验证过的模式：自部署用户获得完整产品，SaaS 用户按 tier 付费换取便利。

📊 权益分界线

维度免费版付费版
并发会话2 个10 个
历史记录保留7 天永久
主机数不限
推送通知仅 Agent 报错全量推送
数据导出无✅
Agent 类型全部可用
Token 看板全部可用

设计要点

  • Agent 类型和 Token 看板不设限 — 属于核心产品体验，开放给所有用户降低试用门槛
  • 主机数不限制 — 限制并发会话已足够对齐成本且用户体验更好
  • 免费版 2 个并发 — "刚好够用但不爽"，保留自然升级动机
  • 免费版 7 天保留 — 覆盖完整工作周，超过则自然转化为付费

🏗 技术方案

选型：结构化权益配置 — 权益定义在配置文件中，运行时根据 users.plan 字段匹配。Plan 变更即时生效。

配置文件

# relay/plans.yaml
mode: saas  # 'saas' | 'self-hosted'

plans:
  free:
    max_concurrent_sessions: 2
    retention_days: 7
    push_notifications: error_only
    data_export: false
    max_daemons: 1

  pro:
    max_concurrent_sessions: 10
    retention_days: -1        # -1 = 永久
    push_notifications: all
    data_export: true
    max_daemons: 5

权益检查流程

请求到达 → JWT 验证（user.id） → 查 DB：SELECT plan FROM users WHERE id = ? → getPermissions(plan, mode) → 按权益 key 判断
设计决策选择理由
Plan 存储位置每次请求查 DB主键查询 <1ms，Plan 升级即时生效，无需重新登录
权益配置位置YAML 文件启动时加载，不额外查 DB；改权益不重启
自部署检测POCKETCTL_MODE 环境变量简单可靠，无需数据库区分

数据库

无需新增字段或表。已有 users.plan VARCHAR(16) DEFAULT 'free' 字段（db.ts:99），已有 getUserPlanAndWhitelist() 函数。

🔍 权益检查点

权益检查位置说明
max_concurrent_sessions Session 创建路由 查用户当前 running / busy 会话数 vs 上限
retention_days 定时清理 cleanStaleEvents() 目前硬编码 90 天，改为按 plan 动态传入
push_notifications 推送逻辑 error_only 时只推 Agent 报错类型
data_export 新增导出路由 检查权益后放行
max_daemons Daemon 注册路由 已有逻辑，值改为从配置读取

📈 扩展性分析

新增套餐（如 Max）

plans:
  free:    { max_concurrent_sessions: 2,  ... }
  pro:     { max_concurrent_sessions: 10, ... }
  max:     { max_concurrent_sessions: 50, priority_support: true, ... }  # 新增
  • plans.yaml 加一个 block
  • users.plan 允许 'max' 值
  • 消费端代码无改动 — getPermissions() 根据 plan 自动匹配

新增权益项

  • 配置文件每个 tier 加一行
  • 消费端加对应 UI / 逻辑
核心原则：权益定义和权益消费解耦。配置文件只管"什么套餐有什么"，代码不知道有几个套餐。

❌ 同期讨论不做的事项

方向结论
会话记录搜索 ROI 低。用户通常只看结论，重复工作让 Agent 重新执行即可
Skill 跨会话/跨机器管理 真实但低频。本质是文件同步问题，与 pocketctl 核心价值无关
团队版 伪命题。核心价值是"个人远程监控自己的 Agent"，团队场景无真实痛点
会话 AI 总结 Claude Code 已自行完成总结 + 选项，额外加工无增量价值
代码 Diff 有用但不改变核心体验，可后续评估

📍 产品定位结论

一个好工具 + 小额副业。

开源 + 自部署模式下全功能可用，社区受益。
SaaS ¥19/月 — 有人付费是惊喜，没人付费也不焦虑。
不指望它成为规模化商业产品。

pocketctl 精准地解决了一个窄而真实的个人痛点——"离开电脑后保持对 AI Agent 的控制和交互"——这是它的核心价值。但该价值不具备自然的商业扩展空间，目标用户群体本身较小。商业野心将放在其他项目中。
