📋 1. 系统概述

pocketctl 是一个远程 AI 编程助手控制系统，允许你在远程机器上运行 AI 编程 Agent（如 Claude Code、OpenCode、Codex），并通过任何设备的浏览器进行监控和交互。

🌐 远程 Agent 管理
通过 Web 界面创建、监控和交互 AI 编程助手会话，支持 Claude Code、OpenCode、Codex 多种 Agent。
📡 终端会话发现
自动发现终端中运行的 Claude Code 会话，通过文件系统监视和 JSONL 实时追踪实现。
🔄 跨设备协同
从 Web 继续终端会话，或从终端恢复 Web 会话，实现无缝的跨设备工作流。
📱 移动端适配
完整支持手机和平板访问，具备响应式布局、底部弹出面板和安全区域适配。
⚡ 实时事件流
基于 WebSocket 的实时双向通信，支持 JSONL 文件追踪和 stream-json 输出解析。
🔔 智能通知
桌面通知、终端横幅、浏览器推送三种通知渠道，确保不错过关键事件。

⚙️ 3. Daemon 守护进程

Daemon 是运行在远程机器上的 Go 程序，负责发现、管理和桥接 AI Agent 进程。

3.1 CLI 命令

命令说明参数
pocketctl daemon start 启动守护进程，连接 Relay 并开始发现 Agent --relay <URL> Relay 地址
--api-key <KEY> 认证密钥
pocketctl daemon stop 停止守护进程（先 SIGTERM，5秒后 SIGKILL） —
pocketctl daemon status 显示守护进程状态：PID、运行时间、连接状态、活跃会话、已发现 Agent —
pocketctl daemon logs 查看守护进程日志 --lines / -n 行数（默认 20）
pocketctl version 显示版本号 —

3.2 内部模块

模块文件职责
Agent 发现 internal/discovery/ 扫描系统 PATH，查找已安装的 Agent CLI：claude、opencode、codex
会话管理 internal/session/ 管理 Agent 进程的完整生命周期：创建、发送消息、杀死、状态更新、标题更新
Claude 适配器 internal/adapter/ 解析 Claude Code 的 stream-json 输出和 JSONL 会话历史文件
文件监视器 internal/watcher/ 监视 ~/.claude/sessions/ 目录，追踪 JSONL 文件，监控进程存活状态
WebSocket 客户端 internal/ws/ 与 Relay 建立 WebSocket 连接，支持指数退避自动重连（1s → 30s，最多 10 次）
通知系统 internal/notify/ macOS 桌面通知和终端横幅推送
PID 管理 internal/daemon/ PID 文件和状态文件管理，位于 /tmp/pocketctl/
协议定义 internal/protocol/ 共享消息类型定义（ClientMessage、DaemonEvent、SessionConfig 等）

3.3 Agent 启动参数

Daemon 使用以下参数启动 Claude Code 进程：

claude -p "<prompt>" \
  --session-id <id> \          # 新会话：指定 session ID
  --resume \                     # 恢复会话：使用 --resume 模式
  --output-format stream-json \  # 流式 JSON 输出
  --verbose \                    # 详细模式
  --permission-mode acceptEdits  # 权限模式
  --allowedTools <tools>        # 可选：限制可用工具

3.4 状态文件

文件路径内容
PID 文件 /tmp/pocketctl/daemon.pid 守护进程的进程 ID
状态文件 /tmp/pocketctl/daemon.state JSON 格式，包含 daemon_id、relay_url、连接状态、启动时间、会话列表

🔌 4. Relay 中继服务

Relay 是基于 Fastify 的中央 WebSocket 路由服务器，负责消息分发、事件持久化和会话管理。

4.1 HTTP 端点

方法路径说明
GET /health 健康检查，返回 {"status": "ok"} 或 {"status": "degraded"}
GET /ws?type=daemon&api_key=XXX Daemon WebSocket 连接端点
GET /ws?type=client&api_key=XXX Client（Web UI）WebSocket 连接端点

4.2 消息路由逻辑

Daemon → Client 路由

事件类型路由行为
session_created持久化会话，自动订阅来源客户端，仅路由到发起方
session_discovered持久化终端会话，广播到所有客户端
agent_text / tool_call / tool_result持久化事件，路由到已订阅的客户端
session_status更新会话状态，路由到已订阅的客户端
session_title_update更新数据库，转发到订阅客户端
session_id_changed更新数据库（sessions + events 表），更新客户端订阅
subagent_discovered增加子 Agent 计数，转发到订阅客户端
ping回复 pong，更新心跳

Client → Daemon 路由

命令类型路由行为
session_create转发到第一个可用的 Daemon，跟踪待处理响应
user_message路由到拥有该会话的 Daemon
session_kill路由到拥有该会话的 Daemon
replay查询数据库中指定序列号之后的事件，发送到客户端
list_sessions查询活跃会话列表（含 Daemon 在线状态）

4.3 数据库 Schema

表名主要字段说明
daemons id, daemon_id (唯一), hostname, agents (JSONB), status, last_heartbeat, created_at 已注册的守护进程信息
sessions id, session_id (唯一), daemon_id (FK), agent_type, cwd, title, source, status, exit_reason, last_activity_at, subagent_count, created_at, updated_at 会话记录，关联到 Daemon
events id (bigserial), session_id, event_type, payload (JSONB), created_at 事件流，支持重放

4.4 过期会话清理

🔄 自动清理策略

• Daemon 离线超过 5 分钟的运行中会话自动标记为 completed

• 超过 1 小时的 pending-* 会话将被清除

🖥️ 5. Web 管理界面

基于 Vue 3 的单页应用，提供完整的 Agent 管理和交互功能。

5.1 页面路由

路由组件功能
/ SessionList 会话列表视图，展示所有活跃会话及其状态
/session/:id SessionDetail 会话详情视图，实时对话和工具调用展示

5.2 会话列表（SessionList）

📊 状态指示器
8 种状态对应不同颜色和脉冲动画，一目了然地展示每个会话的当前状态。
🏷️ 来源标签
区分「终端」发现的会话和「Web」创建的会话，使用不同颜色徽章。
⏰ 相对时间
中文相对时间显示（刚刚、X分钟前、X小时前），每 60 秒自动刷新。
🔗 断开覆盖
Daemon 离线时显示虚线蓝色边框和断开状态覆盖层。

5.3 会话详情（SessionDetail）

💬 对话界面
用户消息（蓝色气泡）、Agent 文本（深色气泡）、工具调用（可折叠卡片）三类型展示。
🔧 工具调用展示
支持 Read、Write、Edit、Bash、Glob、Grep、WebSearch、Agent 等工具图标，可折叠输入输出。
🤖 子 Agent 卡片
紫色左边框可展开卡片，显示子 Agent 类型、描述和嵌套消息。
📋 生命周期时间线
底部水平时间线展示会话状态里程碑，当前状态高亮绿色。
🔄 恢复会话
退出 Banner 提供「恢复会话」按钮（Daemon 在线时可用），支持继续对话。
📱 移动端优化
安全区域适配、底部弹出面板、触摸友好控件，完整的移动端体验。

5.4 新建会话对话框

通过模态对话框创建新会话，支持：

  • Agent 类型选择器（Claude Code、OpenCode）
  • 工作目录输入（持久化到 localStorage）
  • 初始提示文本域
  • 移动端：底部弹出面板（Bottom Sheet）样式

5.5 连接状态横幅（ConnectionBanner）

  • Relay 连接指示器（绿/红圆点）
  • 重连中动画
  • 每个离线 Daemon 的独立横幅（含主机名和离线时间）
  • 多 Daemon 聚合展示，可展开详情

5.6 Composables

Composable功能
useWebSocket WebSocket 单例管理，指数退避重连（1s→30s），Daemon 在线状态追踪，事件处理器注册
useRelativeTime 中文相对时间格式化（刚刚/X分钟前/X小时前/MM-DD HH:mm），60秒自动刷新
useNotifications 浏览器通知管理，终端状态通知，页面内查看时抑制通知，点击导航到会话

📡 6. WebSocket 通信协议

所有消息均为 JSON 格式，通过 type 字段区分消息类型。

6.1 控制消息

Daemon → register — 注册 Daemon（含 daemon_id、hostname、agents 列表）
Relay → register_ack — 确认注册（含 status、connection_id）
Daemon → ping — 心跳探测（每 15 秒）
Relay → pong — 心跳回复

6.2 客户端命令

类型方向字段说明
session_create Client → Relay → Daemon agent, cwd, prompt 创建新会话
user_message Client → Relay → Daemon session_id, content 发送消息到会话
session_kill Client → Relay → Daemon session_id 终止会话
replay Client → Relay session_id, last_seq 请求事件重放
list_sessions Client → Relay — 获取活跃会话列表

6.3 Daemon 事件

类型关键字段说明
session_created session_id, title 新会话已创建
session_discovered session_id, status, cwd, title, source="terminal" 发现终端会话
agent_text session_id, text, streaming Agent 文本输出
tool_call session_id, call_id, tool, input 工具调用
tool_result session_id, call_id, output 工具返回结果
session_status session_id, status, cost_usd, turns, exit_reason, last_activity_at 会话状态变更
session_title_update session_id, title 会话标题更新
session_id_changed session_id, old_session_id 会话 ID 变更
subagent_discovered session_id, agent_id, call_id, subagent_desc, subagent_type 发现子 Agent
error session_id, error 错误事件

6.4 Relay 生成的状态消息

类型触发条件说明
daemon_status: online Daemon 注册 广播到所有客户端，含 hostname、agents 列表
daemon_status: offline Daemon 断开 广播到所有客户端，所有关联会话覆盖 disconnected 状态

🔄 7. 会话生命周期

pocketctl 使用 8 状态状态机管理会话生命周期：

running waiting_approval idle exited disconnected completed error killed

状态说明

状态颜色说明
running🟢 绿色Agent 正在执行任务
waiting_approval🟡 黄色等待用户审批工具调用
idle🔵 蓝色Agent 空闲，等待用户输入
exited⚪ 灰色Agent 进程已退出（可恢复）
disconnected⚪ 虚线Daemon 离线，仅覆盖显示（不持久化到数据库）
completed🟢 绿色任务正常完成
error🔴 红色异常错误退出
killed🩷 粉色用户手动终止

退出原因

退出原因说明
user_interrupt用户中断
normal_exit正常退出
process_crash进程崩溃
signal_kill信号杀死
unknown未知原因

会话来源

来源标签说明
terminal终端通过文件监视自动发现的终端 Claude Code 会话
daemonWeb通过 Web 界面创建的会话

🔍 8. 终端会话发现

pocketctl 能够自动发现运行在终端中的 Claude Code 会话，实现跨设备协同。

8.1 文件系统监视（Watcher）

特性详情
监视目录~/.claude/sessions/
监视机制fsnotify 实时事件 + 每 30 秒定时扫描兜底
事件类型discovered（新会话）、changed（状态变更）、removed（文件删除）
过滤发现时自动跳过 PID 已死亡的会话

8.2 JSONL 实时追踪（Tailer）

特性详情
文件路径~/.claude/projects/<encoded-path>/<session-id>.jsonl
读取策略1 秒轮询间隔，追踪文件偏移量
启动模式FromStart（从头读取，用于已发现会话）/ FromEnd（仅读新内容）
标题提取读取前 500 行，提取第一个真实用户消息作为会话标题

8.3 子 Agent 发现

  • 扫描 <session-dir>/subagents/ 目录
  • 读取 agent-<id>.meta.json 文件获取子 Agent 元数据
  • 为每个子 Agent 启动独立的 JSONL Tailer
  • 所有事件标记 agent_id 字段以区分来源

8.4 进程存活监控

  • 每 2 秒检查一次 PID 存活状态
  • 进程从存活转为死亡时触发 ProcessStateChange 事件
  • 避免重复通知（仅状态变更时触发）

🔔 9. 跨设备通知

pocketctl 提供三种通知渠道，确保用户在不同设备上都能及时收到关键事件。

🖥️ macOS 桌面通知
通过 osascript 调用 macOS 通知中心发送桌面推送。当 Web → 终端的消息完成时触发。
📟 终端横幅
通过 TTY 设备直接写入 ANSI 彩色横幅。自动查找进程对应的 TTY 设备（ps -o tty=）。
🌐 浏览器通知
使用 Web Notifications API，对终端状态（exited、error、killed、completed）发送通知。用户正在查看会话页面时自动抑制。

通知触发场景

场景桌面通知终端横幅浏览器通知
Web → 终端消息完成✅✅—
会话退出——✅
会话错误——✅
会话被杀——✅
会话完成——✅

🐳 10. 部署方案

10.1 Docker Compose 部署

推荐使用 Docker Compose 一键部署 Relay、Web UI 和 PostgreSQL：

服务镜像端口说明
postgres postgres:17-alpine 5432 数据库服务，启用健康检查，持久化数据卷
relay 自建（Node 22-alpine） 8080 WebSocket 中继服务
web 自建（多阶段构建 + Nginx alpine） 3000 Web 前端，Nginx 反向代理 /ws 到 Relay

10.2 环境变量配置

变量默认值说明
POCKETCTL_API_KEY ""（空=无认证） Relay WebSocket 认证密钥
DATABASE_URL postgresql://localhost:5432/pocketctl PostgreSQL 连接字符串
PORT 8080 Relay 监听端口

10.3 Daemon 部署

Daemon 需要编译并在远程机器上运行：

# 编译
go build -o pocketctl ./cmd/pocketctl

# 启动守护进程
./pocketctl daemon start \
  --relay ws://your-relay-host:8080 \
  --api-key your-secret-key

# 查看状态
./pocketctl daemon status

# 查看日志
./pocketctl daemon logs -n 50

10.4 Web UI 配置

配置项存储位置说明
