📋 功能概述

为每个 Session 新增 LastActivityAt 时间戳，用于追踪会话的最后活跃时间，并按活跃度排序展示。覆盖以下场景：

  • Daemon 创建会话 — 初始化时设为 StartedAt，每次 JSONL 事件更新
  • Terminal 发现会话 — 注册时设为 StartedAt，JSONL tailer 事件更新
  • 状态变更 — SetSessionStatus / SetSessionExited 更新
  • 用户消息 — SendMessage 更新
  • 会话终止 — KillSession 更新
  • Resume 终端 — sendToIdleTerminal 更新
  • 排序规则 — 活跃会话在前（最近活跃优先），已退出会话在后

🐛 Bug 修复记录

Bug #1: Terminal Session 的 LastActivityAt 不更新

严重 已修复

现象：终端发现的 session 虽然持续产生 JSONL 事件，但 last_activity_at 始终停留在初始值（StartedAt）。

根因：cmd/pocketctl/main.go 的 handleWatcherEvents 中，JSONL tailer 读取事件后只发送到 outputCh，未调用更新 LastActivityAt。Daemon 创建的 session 有 readOutput 方法处理，但 terminal session 走的是完全不同的代码路径。

修复：

  • internal/session/manager.go — 新增 UpdateLastActivity(sessionID string) 公开方法
  • cmd/pocketctl/main.go — terminal session 的 JSONL tailer 收到事件后调用 sm.UpdateLastActivity()
// main.go — terminal session tailer loop
if len(events) > 0 {
    sm.UpdateLastActivity(evt.Session.SessionID)
}

Bug #2: E2E 测试 session ID 不匹配导致假失败

中 已修复

现象：TestSessionExited_ReadOutputLastActivityAt 超时（10秒内未收到目标事件）。

根因：CreateSession() 返回的是 pending-xxxx 前缀的临时 ID，而 readOutput 发出的 session_status 事件使用的是 adapter 解析后的真实 session ID（la-test-session），两者不匹配，断言 evt.SessionID == sid 永远为 false。

修复：改为接受 pending ID 或 mock session ID 两种可能。
